Before Sending a Technical Request

When reporting a technical issue, providing useful context can make troubleshooting considerably easier. Mention the page or project where the issue occurred, the approximate time, what you expected to happen, and what actually happened.

If an automation workflow produced an unexpected result, describe the relevant workflow stage whenever possible. For example, the issue might involve content generation, blog creation, internal links, RSS output, repository publishing, analytics integration, advertising integration, or deployment.

Avoid sending passwords, private API keys, authentication tokens, payment information, private credentials or other confidential information through ordinary email.
